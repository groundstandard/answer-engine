Overview

What the API does, in one line.

You send a question (and optionally your own indexed documents). The engine retrieves supporting evidence, drafts an answer, extracts each factual claim, verifies every claim against the evidence, and applies a policy gate. It returns one of three states — never an unverified guess:

VERIFIED claims fully supported   QUALIFIED partial / caveated   REFUSED not enough evidence

Base URL

https://web-production-c8c1.up.railway.app

All endpoints below are under /v1. Interactive reference is at /docs.

Authentication

Every /v1 call needs a key.

Send your key in the X-API-Key header (a JWT via Authorization: Bearer <token> also works). Keys are issued by an administrator — they are shown once and stored only as a hash.

Get a key (admin only)

# Admin mints a key with the service key curl -X POST https://web-production-c8c1.up.railway.app/v1/auth/api-keys \ -H "X-Service-Key: <SERVICE_KEY>" -H "Content-Type: application/json" \ -d '{"tenant_id":"<TENANT_ID>","role":"api_client","name":"my-app"}'
🔑 The response contains api_key (starts with ae_) once. Store it securely — it cannot be retrieved again.

POSTAsk a question

/v1/query — run the full evidence-gated pipeline.

curl -X POST https://web-production-c8c1.up.railway.app/v1/query \ -H "X-API-Key: ae_your_key" -H "Content-Type: application/json" \ -d '{"query":"What is the first rank in Brazilian Jiu-Jitsu?", "tenant_id":"<TENANT_ID>"}'

Response

{ "final_decision": "VERIFIED", "response_text": "The first rank in Brazilian Jiu-Jitsu is the white belt.", "confidence_summary": "Claim support: 100%. All thresholds met.", "citations": [{"source_name":"BJJ Reference","snippet":"..."}], "uncertainty_notes": [], "trace_id": "….", "latency_ms": 14230 }
FieldMeaning
queryRequired. The user's question.
tenant_idRequired. Your tenant UUID (scopes evidence + policy).
domain_hintOptional. e.g. medical, legal — applies a stricter policy.

POSTStreaming

/v1/query/stream — same input, live pipeline events (SSE).

Returns text/event-stream. Each stage (classification → retrieval → claims → verification → policy → final) emits an event as it completes — ideal for showing a live progress UI.

POSTAdd a document

/v1/documents/index — feed your own evidence.

Send inline text, or a base64-encoded PDF (text is extracted server-side).

# Inline text curl -X POST https://web-production-c8c1.up.railway.app/v1/documents/index \ -H "X-API-Key: ae_your_key" -H "Content-Type: application/json" \ -d '{"source_id":"<SOURCE_ID>","tenant_id":"<TENANT_ID>", "content":"White belt is the first rank in BJJ.","title":"BJJ basics"}' # PDF: send "pdf_base64" instead of "content"

Manage sources

Sources group your documents and carry a trust tier (1–5).

GET/v1/sources?tenant_id=… — list   POST/v1/sources — create   DEL/v1/sources/{id}?tenant_id=… — delete

curl -X POST https://web-production-c8c1.up.railway.app/v1/sources \ -H "X-API-Key: ae_your_key" -H "Content-Type: application/json" \ -d '{"tenant_id":"<TENANT_ID>","source_name":"BJJ Reference","trust_tier":5}'

POSTFeedback

/v1/feedback — rate an answer (drives calibration).

curl -X POST https://web-production-c8c1.up.railway.app/v1/feedback \ -H "X-API-Key: ae_your_key" -H "Content-Type: application/json" \ -d '{"query_log_id":"<QUERY_ID>","rating":5}'

Answer states

StateWhenWhat to do
VERIFIEDAll claims supported above threshold.Show response_text with citations.
QUALIFIEDPartial support, or sources conflict.Show answer + uncertainty_notes.
REFUSEDNot enough / not trusted enough evidence.Show a "no confident answer" message.

Errors & limits

CodeMeaning
401Missing/invalid key — check X-API-Key.
403Key lacks the required role.
429Rate limit exceeded — slow down and retry.
503A backing store is temporarily unavailable.
The engine never returns an unverified guess. If it can't verify, it refuses — that is the intended behavior, not an error.
